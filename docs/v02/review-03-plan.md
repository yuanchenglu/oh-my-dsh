## 2. Findings

### 🟡 F1：M2 AC-4 测试是空转用例（vacuous test）

- **位置**：docs/v02/03-plan.md，M2 节步骤 3，用例「AC-4：关键词 < 4 字符的否定型约束不触发拦截」
- **问题描述**：用例使用约束 `"不允许删"`。提取正则 `(?:不能|不要|不得|禁止|严禁|不允许|千万别|绝对不)[^，。；、！？\n]{2,60}` 要求前缀后**至少 2 个字符**，而"删"只有 1 个字符——该约束根本不会通过 `extractHardConstraints` 进入会话约束表。随后 `_preExecute` 因 `constraints.size === 0` 直接 `next()` 放行，测试通过但**从未执行到 `keyword.length < 4` 守卫分支**。即使实现者删掉这个守卫，测试依然全绿——零回归保护。这正是 v0.1 review G1 痛批的"测试名与断言不符"的同类问题，不能在新文档里重演。
- **修复建议**：把约束文本改为 `"禁止删表"`（前缀"禁止" + 关键词"删表" = 2 字符，能通过提取正则、进入约束表），exec arguments 中含"删表"，断言 `next()` 被调用（放行）。如此，删掉 `< 4` 守卫会返回 deny、测试变红，构成真正的回归测试。

### 🟡 F2：M0 验收的测试总数错误

- **位置**：docs/v02/03-plan.md，M0 节验收第 2 条
- **问题描述**：文中写"v0.1 的 74 个测试 + 新增 8 个 = 82 个"。`tests/shared/messages.test.ts` 的实际用例数为：contentToText 3 个 + extractLastUserMessage 2 个 + estimateTokens 2 个 = **7 个**，总数应为 **81**。弱 AI 执行者按 82 验收会与实际运行结果对不上。
- **修复建议**：改为"v0.1 的 74 个 + 新增 7 个 = 81 个"（或把 messages.test.ts 补到 8 个用例并同步计数）。

### 🟢 F3：PRD 3.2.5 AC-1 的 isError 物化断言无覆盖路径

- **位置**：docs/v02/03-plan.md，M2 节 AC-1 用例
- **问题描述**：用例只断言插件侧返回 `{ kind: 'deny', reason }`。PRD 3.2.1 声称的"dsh 把 reason 物化为 `isError: true` 工具结果喂回模型"是 dsh 运行时行为（packages/core/tools/src/index.ts:1488-1498），mock ctx 环境测不到。当前无任何环节验证这个端到端断言。
- **修复建议**（可选）：在 M2 验收处注明"isError 物化属 dsh 运行时行为，由 M4 真实安装验证兜底"；或在 M4 冒烟步骤补一次真实对话中的 deny 验证（需要 DEEPSEEK_API_KEY）。

### 🟢 F4：里程碑内实现先于测试

- **位置**：docs/v02/03-plan.md，M0-M3 各节结构
- **问题描述**：各里程碑均为"实现代码在前、测试代码在后"，非严格 TDD 顺序。对弱 AI 执行者，"代码 + 测试同里程碑交付"可接受，不阻塞。
- **修复建议**（可选）：各 M 节加一句"建议先建测试文件再写实现，验收以全绿为准"。
